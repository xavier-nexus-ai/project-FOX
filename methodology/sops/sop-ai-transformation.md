## 1. Overview

### What This Service Is

The AI System Build is a 90-day engagement that turns a business's existing intellectual property, processes and expertise into a working AI-powered operating system.

Not a chatbot. Not a prompt library. A production-ready framework of specialist AI agents that think, decide and deliver using the client's own methodology, language and judgement.

The output is a deployable system the client owns permanently. It runs inside Claude Code (or compatible AI platforms), and the client can use it to serve their own customers at scale without rebuilding from scratch each time.

### Who It's For

Any business that has:
- Structured intellectual property (frameworks, methodologies, named processes)
- Repeatable delivery workflows (how they serve clients, step by step)
- Expert judgement that currently lives in people's heads
- A desire to scale delivery without proportionally scaling headcount

This includes agencies, consultancies, coaching businesses, professional services firms, SaaS companies, training organisations, and education businesses.

### What You Get

Every engagement produces 10 core deliverables:

| # | Deliverable | What It Is |
|---|-------------|------------|
| 1 | Named Methodology | Your IP structured into a branded, phased transformation with clear progression |
| 2 | Diagnostic Instruments | Assessment tools that make the framework intelligent (intake, scoring, progress) |
| 3 | Playbooks | Step-by-step operational guides for each phase of your methodology |
| 4 | Templates | Document and deliverable templates your framework produces |
| 5 | AI Agents | Specialist AI personas with your IP, voice and decision logic baked in |
| 6 | Skills | Modular expertise modules agents draw on (your SOPs turned into reusable knowledge) |
| 7 | Workflows | Phase execution sequences defining how agents coordinate |
| 8 | Tasks | Discrete work units agents execute within each phase |
| 9 | Client Operating System (COS) | Single source of truth tracking every client's progress through your methodology |
| 10 | Deploy Script + Scaling Roadmap | One-command deployment to new client projects, plus a commercial scaling plan |

### How This Differs By Business Type

For education and course businesses, the structure is more templated because their delivery models are similar. For general businesses (agencies, consultancies, services firms), the engagement is more bespoke. The phases are the same, but the depth of IP extraction, the agent architecture, and the commercial model are all unique to the business.

### Investment and Time Commitment

- **Duration:** 90 days (12 weeks)
- **Client time commitment:** 4-6 hours per week (interviews, reviews, decisions)
- **Heaviest client involvement:** Weeks 5-6 (IP extraction interviews)
- **Lightest client involvement:** Weeks 9-11 (framework construction, mostly our side)

## 2. The Three Phases

The engagement follows three phases. Each builds on the last. You cannot skip ahead.

```
IMMERSION          MAPPING              TRANSFORMATION
Weeks 1-4          Weeks 5-8            Weeks 9-12
Learn + Setup      Extract + Design     Build + Deploy
```

| Phase | Purpose | Client Experience | Key Output |
|-------|---------|-------------------|------------|
| **Immersion** | Get AI-literate, set up the environment, build confidence | Education sessions, hands-on exercises, a quick win build | AI Possibilities Map, Industry Report, configured environment |
| **Mapping** | Extract all IP and design the system architecture | Deep interviews, methodology naming, commercial planning | IP Vault, Named Methodology, Diagnostics, Constraint Map, Leverage Plan |
| **Transformation** | Build the working framework and deploy it | Review cycles, QA validation, training, first deployment | Complete AI framework with all 10 deliverables |

**Blocking gates** sit between each phase. Every required deliverable must be complete before advancing. This prevents building on weak foundations.

## 4. Phase 1 - Immersion (Weeks 1-4)

**Purpose:** Get the client AI-literate, set up their technical environment, and give them a tangible quick win.

**Why this comes first:** Everything in Mapping and Transformation requires the client to understand how AI agents work, what a COS does, and how to operate Claude Code. Without this foundation, IP extraction interviews are shallow and framework reviews are surface-level.

### 4.1 AI Literacy Education (Weeks 1-2)

**What happens:** Conversational education sessions adapted to the client's current AI knowledge level.

The AI Literacy Coach first assesses where the client sits (beginner, intermediate, advanced) through a few targeted questions. Then teaches to that level. No rigid curriculum. The six core topics are woven into natural conversation:

1. **What agents are** - Specialist AI sessions with defined identities, tasks and context. Like hiring a specialist contractor who already knows your business.
2. **What skills are** - Focused knowledge modules agents can draw on. If an agent is a consultant, a skill is the specialist handbook they reference.
3. **What the COS is** - The single source of truth that tracks every client's progress. The system's memory between sessions.
4. **How multi-chat workflows work** - One persistent coordinator, specialist agents spawning in separate sessions, handoff documents carrying context between them.
5. **AI possibilities for their industry** - Where AI creates leverage in their specific business: delivery augmentation, IP activation, client experience, operations.
6. **Claude Code as a platform** - How the runtime works, key commands, session persistence, cost awareness.

**Deliverables:**
- AI Possibilities Map (structured opportunities by category with feasibility and impact ratings)
- AI Literacy Assessment (level assessment, concept comprehension, strengths, gaps, recommendations)

### 4.2 Industry AI Analysis (Weeks 2-3)

**What happens:** Live research into the client's industry to understand the AI landscape they're operating in.

Covers five dimensions:
1. **Industry AI landscape** - Overall adoption rate, common use cases, maturity, platforms, regulatory considerations
2. **Competitor AI usage** - Who's using AI, how, at what price points, how the market is responding
3. **Opportunity gaps** - Unmet needs AI could address, white space uniquely suited to this client's IP
4. **Risk and threat assessment** - Commoditisation risk, new entrants, shifting client expectations
5. **12-month trend forecast** - Where the industry is heading and how the 90-day program timeline fits

Every section ends with a "So What for [Client Name]?" that connects findings to their specific situation.

**Deliverable:** Industry AI Report (1,500-3,000 words with top 3 opportunities, top 3 risks, strategic recommendations)

### 4.3 Stack Configuration (Weeks 3-4)

**What happens:** Technical setup and hands-on training.

Four steps:
1. **Audit** - Check Claude Code, Node.js, Git, existing tools, project structure
2. **Configure** - Install only the MCP servers the client actually needs (Filesystem always; Browser, Notion, Google Drive, Slack, GitHub as relevant)
3. **Teach** - Four practical exercises: loading an agent, reading the COS, running a multi-chat workflow, testing MCP servers
4. **Validate** - Systematic pass/fail check of every component

**Deliverable:** Stack Validation Report (environment summary, server list, validation results, training checklist, known issues)

### 4.4 Quick Win Build (Week 4)

**What happens:** Hands-on session where the client builds something tangible using AI tools (Lovable, Cursor, or similar vibe-coding platforms).

This is not agent-driven. It's the delivery lead working alongside the client to create something they can immediately show others: a proposal generator, a client dashboard, a quiz, a calculator, a simple tool.

**Purpose:** Build confidence. Show the client what's possible before the deep extraction work begins. They enter Mapping energised, not apprehensive.

### Immersion Exit Gate

All of these must be true before entering Mapping:

- [ ] AI literacy confirmed (client understands agents, skills, COS, multi-chat workflows)
- [ ] AI Possibilities Map completed
- [ ] Industry AI Report completed
- [ ] Stack configured and validated (at minimum: Claude Code + Filesystem MCP working)
- [ ] Client can independently load an agent, paste a prompt, and navigate the output
- [ ] Quick win build completed

## 5. Phase 2 - Mapping (Weeks 5-8)

**Purpose:** Extract everything the client knows, then structure it into a system design.

**Why this is critical:** The quality of IP extraction directly determines the quality of the final framework. Shallow extraction produces a generic system. Deep extraction produces something that genuinely thinks like the client's best people.

**Non-negotiable dependency chain:**
```
IP Extraction (Weeks 5-6)
    ↓
Methodology Architecture (Weeks 6-7)
    ↓
Diagnostics Design (Week 7)        ← parallel with →    Constraint Mapping (Weeks 7-8)
                                                              ↓
                                                         Leverage Planning (Weeks 7-8)
```

IP Extraction must complete before anything else. You cannot structure what you haven't extracted.

### 5.1 Business Workflow Mapping

**What happens:** Before extracting any IP, map the complete business from end to end.

This creates a three-level workflow map covering every core product/service from initial enquiry through fulfilment. It's the skeleton that all extracted IP fits into.

**Outputs:**
- Structured workflow map (JSON format for machine use)
- Visual workflow map (HTML for human review)
- Impact scoring per workflow (time investment, revenue proximity, automation opportunity, failure impact)

### 5.2 IP Extraction (Weeks 5-6)

**What happens:** The most important work in the entire engagement. Multiple deep-dive interview sessions to extract five categories of intellectual property.

**The five IP categories:**

| Category | What It Captures | Minimum Required | Example |
|----------|-----------------|------------------|---------|
| **Frameworks** | Structured approaches to solving problems. Named processes with steps, inputs, outputs. | 2+ | "The Growth Flywheel", "The Clarity Method" |
| **SOPs** | Standard operating procedures. Trigger, steps, outputs, who does what. | 3+ | Client onboarding process, monthly reporting flow |
| **Judgement Calls** | Tacit decision heuristics. The rules experts follow instinctively. | 5+ | "When to recommend restructuring vs optimisation" |
| **Vocabulary** | Unique language, terms, phrases. Captured in the client's own words. | — | "Strategic drift", "activation rate", "channel saturation" |
| **Delivery Sequences** | How clients journey through the methodology. Phases, milestones, touchpoints. | — | 90-day engagement lifecycle, quarterly review cadence |

**How extraction works (the DEPTH model):**

- **D**ocument first - Read everything the client has provided before asking a single question
- **E**licit through scenarios - Never "what is your process?" Always "imagine a client comes to you with..."
- **P**robe the gaps - When the expert jumps from step 2 to step 4, something happened at step 3. Find it.
- **T**est understanding - Reflect back what you heard. Let the expert correct and refine.
- **H**unt the tacit - Push past "I just know" to find the actual signals. "Think of the last time this happened. What told you?"

**Key principles:**
- One question at a time. Never a wall of questions.
- The expert's actual language IS intellectual property. Never paraphrase.
- When they say "it depends" - probe for exactly what it depends on. Get contrasting examples.
- Extraction is archaeology, not interrogation.

**This is multi-session work.** Expect 3-5 sessions of 60-90 minutes each. Progress checkpoints after every session so work can resume cleanly.

**Client time commitment peaks here:** This is the most demanding period for the client. 4-6 hours across Weeks 5-6.

### 5.3 Methodology Architecture (Weeks 6-7)

**What happens:** All extracted IP gets structured into a named, phased methodology.

The process:
1. Survey the raw IP. How many frameworks, SOPs, judgement calls? What patterns emerge?
2. Identify the transformation arc. Where does the client's customer start (pain), where do they end (transformation), what are the 3-6 major shifts between?
3. Propose a methodology structure. 3-7 phases, each with: name, purpose, entry criteria, key frameworks, activities, deliverables, exit criteria, typical duration.
4. Name the methodology collaboratively. 3-5 naming options proposed. The client makes the final choice. This is a branding decision they must own.

**Common naming patterns:**
- "The [X] Method" (The Clarity Method, The Ignition System)
- "[ACRONYM] Framework" (TORQUE, DEPTH)
- Metaphor-based (The Growth Flywheel, The Alignment Engine)
- Client's name + proprietary term

**Deliverable:** Methodology Map (named methodology with tagline, phase definitions, executive summary, framework-to-phase mapping, build recommendations)

### 5.4 Diagnostics Design (Week 7)

**What happens:** Assessment tools are designed that make the framework intelligent. Without diagnostics, every user gets the same experience.

Four types of diagnostic instruments:

1. **Intake Assessment** - 10-20 questions determining starting point and profile. Every question traces back to a framework or judgement call in the IP vault. Produces 3-5 result profiles with specific recommendations per profile.
2. **Scoring Rubrics** - 3-5 maturity levels per dimension with clear observable indicators at each level. Dimensions derived from methodology phases.
3. **Phase Progress Diagnostics** - Checkpoint assessments at each methodology phase boundary. What must be true to advance? What stall patterns indicate someone is stuck?
4. **Triage Tools** (if applicable) - For clients with multiple offers, routes users to the right track.

**Deliverable:** Diagnostic Tools document (complete designs with intake assessment, scoring rubrics, progress diagnostics, build specifications)

### 5.5 Constraint Mapping (Weeks 7-8)

**What happens:** An honest assessment of what should be automated, what should be augmented, and what must stay human.

Every process, touchpoint and decision point gets classified into one of four categories:

| Category | Definition | Example |
|----------|-----------|---------|
| **Fully Automated** | AI end-to-end, no human intervention. Well-defined, repeatable, low-stakes errors. | Email templates, scheduling, report generation |
| **AI-Assisted** | AI does it, human reviews. Clear patterns but occasional edge cases. | Draft recommendations, analysis summaries |
| **AI-Augmented** | Human leads, AI supports. Significant judgement required. | Strategy sessions, coaching conversations |
| **Human Only** | No AI involvement. Deep empathy, trust or relationship required. The human touch IS the value. | Crisis intervention, sensitive feedback |

Also maps build-order dependencies (what must be built before what) and produces a risk analysis: for every AI-involved process, what happens if it produces incorrect output?

**Deliverables:**
- Constraint Map (delivery process analysis, blocking dependencies, risk register)
- AI-Human Boundary document (complete classification with summary counts)

### 5.6 Leverage Planning (Weeks 7-8)

**What happens:** All Mapping outputs get synthesised into a commercial strategy.

Five elements designed:
1. **Pricing model** - Value-based (outcomes, not time), tiered, recurring, or hybrid
2. **Offer packaging** - Tier structure, feature allocation per tier, capacity design, upsell paths
3. **Delivery model redesign** - Which steps AI handles, how the client's role changes (deliverer to curator/reviewer), new capacity
4. **Scaling strategy** - Three phases: Foundation (launch, validate), Expansion (increase capacity, add offers), Leverage (maximum automation)
5. **Financial projections** - Conservative, moderate and optimistic scenarios

**Deliverables:**
- Leverage Plan (current state, future state, pricing, packaging, delivery redesign, financials)
- Scaling Roadmap (phased plan with goals, actions, milestones, revenue targets)

### Mapping Exit Gates

All of these must be true before entering Transformation:

- [ ] Business workflows mapped end-to-end
- [ ] IP Vault populated: 2+ frameworks, 3+ SOPs, 5+ judgement calls
- [ ] Methodology named and structured with phases
- [ ] Diagnostics designed (intake + scoring + progress)
- [ ] Constraint map created (every process classified)
- [ ] Leverage plan completed with financial projections
- [ ] Scaling roadmap delivered

## 6. Phase 3 - Transformation (Weeks 9-12)

**Purpose:** Convert everything from Mapping into a working, deployable AI framework.

**Client involvement drops here.** The heavy lifting is on the delivery side. The client's role shifts to reviewing, approving and learning to operate the framework.

### 6.1 Framework Construction (Weeks 9-11)

**What happens:** All 10 deliverables get built using specialised builder skills in a prescribed order.

**Build sequence:**

| Order | Component | Builder Skill Used | What Gets Created |
|-------|-----------|-------------------|-------------------|
| 1 | COS Schema | cos-design-expert | `cos.template.yaml` - state tracking for the client's methodology |
| 2 | Framework Architecture | framework-pattern-expert | Overall architecture decisions documented |
| 3 | Agents | agent-design-expert | Agent `.md` files with IP, voice and decision logic baked in |
| 4 | Skills | skill-design-expert | Skill `SKILL.md` files transferring the client's expertise |
| 5 | Methodology Wiring | methodology-structuring | Methodology phases mapped to agents and workflows |
| 6 | Diagnostics | diagnostic-builder | Assessment templates and scoring tools |
| 7 | Playbooks | playbook-builder | Operational guides per phase |
| 8 | Gates | blocking-gate-designer | Quality gates with binary pass/fail criteria |
| 9 | Deploy Script | deploy-script-builder | One-command deployment to customer projects |
| 10 | CLAUDE.md | claude-md-builder | Navigation brain that every agent reads |

Plus: workflows, tasks, checklists, and README.

**This is multi-session work.** 4-8 sessions across Weeks 9-11 with progress checkpointing after every major component group.

**The separation principle:** The framework being built is entirely separate from the builder framework being used to build it. The client's framework goes into `docs/client-framework/` and must be completely self-contained. Every file any agent references must exist inside that folder.

### 6.2 QA Validation (Weeks 11-12)

**What happens:** Independent quality assurance across 10 categories. Binary pass/fail for everything.

| # | Validation Category | What's Checked |
|---|---------------------|----------------|
| 1 | Structural | All required directories and files exist |
| 2 | Frontmatter | Every agent and skill file has valid metadata |
| 3 | Agent | Activation protocols present, dependencies correct, scope defined |
| 4 | Skill | SKILL.md files well-formed, referenced by agents correctly |
| 5 | COS Schema | Phases match methodology, gates present and correct |
| 6 | Workflow | Sequences make sense, referenced agents exist |
| 7 | IP Fidelity | Framework reflects client's actual IP (not generic patterns), client vocabulary used |
| 8 | Deploy Script | Creates correct structure when run |
| 9 | CLAUDE.md | References all agents and skills correctly, no orphans |
| 10 | Cross-Reference | No orphaned references anywhere, no missing dependencies |

**QA is independent.** The validator does not read the builder's progress notes. It validates what exists, not what was intended. If something fails, it routes back for targeted fixes and then re-validates the full suite.

**Deliverable:** QA Report (comprehensive validation results with per-check pass/fail and severity ratings)

### 6.3 Deployment (Week 12)

**What happens:** The framework gets deployed, the client gets trained, and the first real customer engagement begins.

**What gets deployed (copied to each customer project):**
- Agents, skills, scripts, workflows, tasks, templates, checklists, README

**What gets generated fresh per customer (NOT copied):**
- COS (unique to each customer, created during their onboarding)
- CLAUDE.md (unique to each customer, generated by the framework's init agent)

**Client training covers:**
- Opening Claude Code and loading agents
- How the COS works
- The spawn/review cycle
- Running each agent for a real customer
- Using skills within agent sessions
- Updating and maintaining the framework
- Deploying to new customer projects
- Troubleshooting common issues

**First deployment:** The client deploys the framework to a real customer project during Week 12 with the delivery lead supporting. This validates the framework works end-to-end in production.

### Transformation Exit Gates

All of these must be true before the engagement closes:

- [ ] All 10 components built and assembled
- [ ] QA validation passed (all critical checks green)
- [ ] Deploy script tested and working
- [ ] CLAUDE.md references correct
- [ ] Client trained on framework operation
- [ ] First customer deployment successful

## 7. What Gets Built - The 10 Deliverables in Detail

### 1. Named Methodology

A branded, phased transformation with 3-7 phases. Each phase has a name, purpose, entry criteria, key activities, deliverables and exit criteria. The methodology is the client's IP structured into a repeatable system.

**Example:** "The Ignition System" (marketing agency) - Audit, Ignite, Scale
**Example:** "The Clarity Method" (consulting firm) - Diagnose, Design, Drive

### 2. Diagnostic Instruments

Assessment tools that route users to the right experience. Intake questionnaire (10-20 questions), scoring rubrics (3-5 maturity levels per dimension), phase progress diagnostics, and optional triage tools.

### 3. Playbooks

Step-by-step operational guides for each phase of the methodology. These are what agents follow when executing work. Written in the client's voice using their vocabulary.

### 4. Templates

Document and deliverable templates the framework produces for end customers. Proposals, reports, assessments, plans - whatever the methodology calls for.

### 5. AI Agents

Specialist AI personas. Each agent has the client's IP, voice, and decision heuristics baked in. An orchestrator coordinates everything. Specialist agents handle specific phases or tasks.

**Typical agent count:** 5-10 depending on methodology complexity.

### 6. Skills

Modular expertise modules agents draw on. The client's SOPs, frameworks and judgement calls turned into reusable knowledge that any agent can reference.

### 7. Workflows

Phase execution sequences defining the order agents activate in, what triggers each step, and how work flows between agents.

### 8. Tasks

Discrete work units within each workflow. Each task has context, inputs, steps, and validation criteria.

### 9. Client Operating System (COS)

A YAML state file that tracks every customer's progress through the methodology. Phases, deliverables, blocking gates, metrics, and an audit trail. This is the framework's memory between sessions.

### 10. Deploy Script + Scaling Roadmap

A one-command script that deploys the framework to a new customer project. Plus a commercial scaling roadmap with phased goals, revenue targets, and capacity projections.

## 9. How It Adapts to Different Business Types

The three phases (Immersion, Mapping, Transformation) are the same for every business. What changes is the depth, emphasis and output at each stage.

### Education and Course Businesses

- **IP extraction focus:** Course content, learning pathways, student progression frameworks
- **Methodology emphasis:** Learning journey design, module sequencing, assessment design
- **Agent architecture:** Course delivery agents, student assessment agents, content creation agents
- **Constraint mapping:** More falls into "fully automated" because delivery is already systematised
- **Leverage angle:** Scale from 1:1 to 1:many without losing personalisation

### Agencies

- **IP extraction focus:** Service delivery processes, client management workflows, quality frameworks
- **Methodology emphasis:** Client engagement lifecycle, team coordination, deliverable production
- **Agent architecture:** Client onboarding agents, project management agents, quality assurance agents, reporting agents
- **Constraint mapping:** Team delivery means more "AI-assisted" (AI drafts, humans review)
- **Leverage angle:** Serve more clients with the same team, enable junior staff to deliver at senior quality

### Consultancies

- **IP extraction focus:** Diagnostic frameworks, strategic models, advisory methodologies
- **Methodology emphasis:** Assessment, design, implementation phases. Judgement calls are the highest-value IP.
- **Agent architecture:** Diagnostic agents, strategy agents, implementation tracking agents
- **Constraint mapping:** More "AI-augmented" and "human only" because the consultant's judgement IS the product
- **Leverage angle:** Productise advisory into a framework that associates can deliver

### SaaS and Product Companies

- **IP extraction focus:** Onboarding processes, customer success workflows, support playbooks
- **Methodology emphasis:** Customer lifecycle, activation, retention, expansion
- **Agent architecture:** Onboarding agents, health scoring agents, support triage agents
- **Constraint mapping:** Highest automation potential because processes are already digital
- **Leverage angle:** Embed AI into the product experience, reduce support load, increase activation

### Professional Services (Legal, Accounting, Engineering)

- **IP extraction focus:** Compliance frameworks, review processes, quality standards
- **Methodology emphasis:** Regulatory-aware workflows, risk assessment, documentation
- **Agent architecture:** Review agents, compliance checking agents, document generation agents
- **Constraint mapping:** Compliance creates firm "human only" boundaries. Risk analysis is critical.
- **Leverage angle:** Automate preparation and research, free professionals for high-value advisory

## 10. Quality Gates and Checkpoints

Every phase transition is gated. All required items must pass before advancing.

| Gate | Between | Required Conditions |
|------|---------|--------------------|
| **Immersion Complete** | Immersion → Mapping | AI literacy confirmed, AI Possibilities Map done, Industry Report done, stack configured and validated, client can operate agents independently |
| **IP Extraction Complete** | Mid-Mapping checkpoint | Business workflows mapped, 2+ frameworks extracted, 3+ SOPs extracted, 5+ judgement calls extracted, methodology named |
| **Mapping Complete** | Mapping → Transformation | All IP extraction gates passed PLUS methodology structured with phases, diagnostics designed, constraint map created, leverage plan completed |
| **Components Built** | Mid-Transformation checkpoint | All agents built, all skills built, COS schema designed, templates/workflows/tasks/checklists created, CLAUDE.md written, deploy script created |
| **QA Passed** | Pre-deployment | Framework assembled, QA validation passed (all critical checks green), deploy script tested, client trained |

**Gate enforcement is strict.** If a gate hasn't passed, the next phase does not start. This is not bureaucracy. It prevents the most common failure mode: building on incomplete foundations.

## 11. Post-Engagement

### What Happens After 90 Days

The engagement ends. The framework doesn't.

The client's project folder becomes their **Master Project** - a permanent workspace where they continue to iterate, improve and extend their framework. It's a living system, not a one-time deliverable.

### Master Project vs Customer Deployments

| Aspect | Master Project | Customer Deployment |
|--------|---------------|-------------------|
| **Lifespan** | Permanent, evolving | Point-in-time snapshot |
| **Purpose** | Develop, improve, extend the framework | Serve a specific customer |
| **Changes flow** | Improvements go here first | Changes stay local to the customer |
| **Updates** | Continuous | Only via explicit redeployment |

When the client improves an agent, adds a new skill, or refines a workflow - that happens in the Master Project. Existing customer deployments don't automatically update. New deployments get the latest version. The client can redeploy to existing customers if they choose, but it's a deliberate action.

### How the Client Maintains the Framework

- **Add new agents** when new capabilities are needed
- **Refine skills** as they learn what works and what doesn't
- **Update the COS schema** if they add new phases or metrics
- **Evolve diagnostics** based on real customer data
- **Extend templates** as new deliverable types emerge

### Support Model

Post-engagement support is defined in the client's contract. Common models:

- **Retainer:** Ongoing access for framework improvements, new agent builds, troubleshooting
- **Ad-hoc:** Pay-per-session for specific improvements or new features
- **Self-service:** Client maintains the framework independently (training in Week 12 covers this)

## 12. Internal Delivery Notes (Staff Only)

This section is for the Njin delivery team only. Do not share with clients.

### Agent Sequence and Dependencies

The agent execution order is non-negotiable within each phase. Dependencies exist because each agent's output is the next agent's input.

**Immersion (can partially parallelise):**
```
Sage (AI Literacy) → Scout (Industry Analysis) → Forge (Stack Config)
```
Sage ideally runs first (AI literacy context improves industry analysis). Scout before Forge (industry context informs stack decisions). But time pressure allows partial overlap.

**Mapping (strict dependency chain):**
```
Cipher (IP Extraction) → Atlas (Methodology) → Prism (Diagnostics) + Nexus (Constraints) → Vector (Leverage)
```
Cipher MUST complete before Atlas. Atlas MUST complete before Prism/Nexus. Prism and Nexus can run in parallel. Vector runs after Nexus.

**Transformation (strict sequence):**
```
Apex (Framework Build) → Sentinel (QA) → Deploy
```

### Common Failure Modes

| Failure | Cause | Prevention |
|---------|-------|-----------|
| Shallow IP extraction | Not enough interview sessions, surface-level questions | Budget 3-5 sessions minimum. Use DEPTH model. Push past "I just know." |
| Generic framework | IP not properly baked into agents/skills | QA checks IP fidelity specifically. Flag if agents sound generic. |
| Methodology naming stalls | Client can't decide | Present 3-5 options with rationale. Set a decision deadline. Move on. |
| Scope creep in Mapping | Client keeps adding "one more framework" | Gate minimum counts exist for a reason. Extract what's needed, note the rest for post-engagement. |
| Week 12 crunch | Earlier phases ran over time | Gates prevent this. If Immersion runs to Week 5, Mapping starts late and something has to compress. Flag early. |

### Session Management

- **Multi-session agents** (Cipher, Apex) checkpoint after every major work batch
- **Progress files** live in `docs/progress/` and enable clean session resumption
- **Each session should end** with: what was completed, what's next, any blockers
- **COS updates happen** after every meaningful change, not batched at session end

### The Spawned Agent Sandbox Rule

**Critical technical constraint:** Spawned agents (subagents) operate in a sandboxed filesystem. No file writes persist from the agent back to the parent session.

This means:
- Agents must output their deliverables as text in their response (not write files)
- The delivery lead's session extracts content from agent output and writes the files
- Read-only agents are unaffected

This is a platform constraint, not a bug. All multi-agent workflows must account for it.

### COS Management Protocol

1. Read `cos.yaml` before every decision
2. Update `cos.yaml` after every meaningful change
3. Add to `change_log` with phase context
4. Check gates before advancing phases
5. Never fabricate COS values. Empty fields are better than made-up ones.
6. COS lives at project root (not in `.claude/`)
