# Judgement Call 6: Revenue-First Prioritisation

**Title:** What Gets PM Time First — Prioritising When Multiple Clients Compete

**The Decision:** When PM bandwidth is limited and multiple clients need attention, which engagement takes priority?

**Hierarchy (in order):**

1. **Paying client work with a hard deadline** — anything with a client-facing milestone or SLA. These go first, always.
2. **Overdue client deliverables** — anything that has slipped past its milestone date. Address these before taking on new work.
3. **Active paying client work (no hard deadline)** — keep momentum, don't let engagements go cold.
4. **Internal projects (Njin itself)** — only get time when client obligations are met. Internal work is never urgent enough to delay a client.

**The $500/hr test:**
Before spending PM time on any task, ask: *Is this $500/hr work?*
- Writing a playbook section, scoping an engagement, running a client review = yes.
- Setting up folder structures, chasing small admin, formatting documents = no. Delegate or automate.

**The fix-before-build rule:**
Never start a new engagement or new phase while a prior one has unresolved blockers. Fix what's broken before adding more.

**When multiple active clients compete for the same timeslot:**
- Which client has the nearest milestone date? That one goes first.
- Which client has the highest revenue value or strategic importance? Use this as a tiebreaker.
- If genuinely equal, pick the one where PM inaction creates the most downstream damage.

**Default:** Revenue-generating, client-facing, overdue work beats everything else. Internal work is scheduled in the gaps, not the calendar.

**Exceptions:**
- An internal build that directly unblocks a client engagement (e.g., a framework tool a client is waiting on) — treat it as client work.
- James has explicitly reprioritised in COS.yaml — defer to that.
