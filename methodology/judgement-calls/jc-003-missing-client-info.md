# Judgement Call 3: How to Handle Missing Client Information

**Title:** Data Access Gate — What to Do When the Client Hasn't Provided Required Docs

**The Decision:** When client documents or access haven't arrived, do you stop, proceed with caveats, or escalate?

**Two categories of missing information:**

| Type | Definition | Action |
|------|-----------|--------|
| **Hard blocker** | Cannot produce correct output without it | Stop. Do not proceed. Log in COS. Escalate to client. |
| **Nice-to-have** | Output will be less specific but still structurally correct | Proceed with a clearly flagged caveat. Chase it in parallel. |

**Hard blockers (cannot proceed without these):**
- CRM admin access — required before any pipeline or automation work
- The Core 12 numbers — required before constraint diagnosis and playbook system instructions
- Contract scope — required before any project planning
- Client approval on Tone of Voice — required before generating any playbook copy

**Nice-to-haves (proceed with caveat):**
- Brand guidelines (if not provided, use inferred tone from website copy + existing materials)
- Current scripts (can draft new ones if none exist — flag as "baseline, not adapted")
- Case studies and testimonials (can add placeholders, fill later)
- Competitor research (can use public research — flag as incomplete)
- Sales recordings (can omit call review framework specifics, add later)

**The 5 Business Day Rule:**
- If hard blocker access is delayed beyond 5 business days, escalate to the client point of contact and document the blocker in the COS. Set a new deadline. Do not wait silently.

**COS update when blocked:**
- Set the relevant data access field to "No (waiting)"
- Add a note: what's missing, when it was requested, new deadline
- Do not advance the status phase until the gate is cleared

**Default:** Stop on hard blockers. Proceed with a documented caveat on everything else. Never let silence on a nice-to-have block progress on the whole engagement.

**Source:** Playbook Creation SOP — Phase 1, Step 5 (Prerequisite Validation) and Step 4 (Data Access fields in COS).
